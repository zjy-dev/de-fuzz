# DeFuzz：研究范围与会话说明

DeFuzz 研究 GCC/LLVM 自动生成的软件防御代码是否符合预期安全不变量，
目的是形成可复现的编译器缺陷证据、修复建议和回归测试，为开源编译器社区提供贡献。
本文为开发会话补充具体研究对象、执行环境和证据要求；项目声明不能保证消除平台检查。
GCC/AArch64 的完整任务见 [可复用实验提示词](prompts/gcc-aarch64-experiment.md)。

## 研究对象、环境与产物

- **对象**：指定版本的 GCC/LLVM 源码、编译器 pass/后端、生成的 IR/汇编，
  以及 stack canary、FORTIFY、CFI、IBT/BTI、PAC、shadow stack 等防御实现。
- **环境**：当前任务明确指定并授权使用的源码工作树、工具链、实验容器、
  本机或 QEMU 测试进程。远程计算资源只在已明确授权时使用；公开源码不意味着
  可以测试部署该软件的第三方服务。
- **操作**：源码分析、不变量整理、checker 编写、独立 C 测试输入生成、
  编译与受控执行、最小化复现、补丁和回归验证、实验统计。
- **产物**：源码位置、编译命令、最小测试程序、IR/汇编差异、退出信号、
  checker 证据、修复建议、回归测试、实验 manifest 和社区报告草稿。

本项目论文草稿的 Threat Model and Scope 已明确：描述被违反的不变量，
不构造可工作的利用程序（见 [main.tex](paper/main.tex)）。
这个边界允许在一次性本地测试进程中观察防御行为；它不把编译器复现程序
扩展为面向真实应用或服务的利用链。

部分动态 checker 会有意触发测试程序中的越界访问或其他无效内存操作，
观察防御是否按预期终止执行。应如实记录该行为，以及测试进程、输入、
编译选项和判定依据。一次崩溃本身不能证明编译器防御有缺陷。

## 常见术语的具体含义

| 术语 | 在本项目中的含义 |
| --- | --- |
| seed / fuzzing campaign | 编译器测试输入／按配置枚举的本地实验 |
| oracle / checker | 根据编译结果或受控执行证据判定不变量的验证器 |
| candidate / reproducer | 待验证的编译器缺陷／演示该缺陷的最小测试 |
| silent failure / bypass | 防御实现没有履行预期不变量；需以 checker 证据限定结论 |
| canary leak / guard residue | 测试二进制中的防御值暴露或残留现象，需说明具体观察范围 |
| payload | 依据上下文判断；编排代码里通常指序列化的 JSON 数据 |
| full | 启用完整功能的实验变体，与 without-rag、without-oracle、bare-agent 区分 |
| 全量 / 完整输入 | 指定编译器、ISA、机制和语料范围内的完整处理，仍受固定预算约束 |
| 一次 / 单次 | 指定范围内一个 repetition，不自动表示三次重复或四变体消融比较 |

保留源码、CVE/PR 编号、编译选项、原始日志和机制名称，不做编码隐藏或关键词替换。
用测试对象、可观察行为和证据解释任务，不把词面当成实验结论。

[experiment_runbook.md](paper/experiment_runbook.md) 为准。

三次重复有不同范围，应使用独立配置和 run_id 记录。

不通过抽样、预算放宽或替换 fixture 获得“全量完成”的结论。
