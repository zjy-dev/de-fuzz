# 跨机制生成的不变量 - 中文解读摘要

这份文档提取了 `cross-mechanism-generated.md` 中 9 条新不变量的核心逻辑中文解读。

## 第一组：出口敏感寄存器/状态擦除类漏洞
*由 001 和 020 种子跨机制生成*

这组规则的共同特征是：编译器本应该在函数返回（出口）前擦除敏感数据（如密钥寄存器、SME 状态等），但由于某些特定的“异常或快速出口”绕过了擦除逻辑，导致敏感数据泄露。

- **XINV-001 (ARM)**：在 `thumb_exit` 函数的快速返回路径（`pops_needed == 0`）中，直接用 `bx` 汇编指令跳出了函数，却忘了发射清零指令。导致 CMSE 安全态等机密数据被泄露给调用者。
- **XINV-002 (AArch64)**：在 SME（可扩展矩阵扩展）状态切换时，某些前置模式的提前返回分支里漏写了清零指令（`zero {za/zt0}`），导致敏感的 SME 寄存器在不该存活的边界后继续存留。
- **XINV-003 (通用)**：编译器在构建单一“常规出口块”时，故意跳过了异常边（如尾调用、非局部跳转）。这导致挂载在“常规出口块”上的寄存器擦除机制对这些异常出口完全失效，变成“裸奔”状态。
- **XINV-004 (通用)**：尾调用在编译器内部属于“异常边”。如果防御机制只遍历“常规返回边”去执行寄存器清理，就会漏掉所有的尾调用出口。
- **XINV-005 (x86)**：在 x86 后端的寄存器擦除循环中，如果上层逻辑因为碰到了一个“异常出口”而决定全局放弃擦除，就会“连坐”导致该函数内的“常规返回路径”也无辜失去了擦除保护。
- **XINV-006 (ARM)**：`thumb_exit` 针对某些特定的返回形式（如 `pop {pc}`）有短路（提前返回）逻辑。这种针对单个出口的特殊处理，导致原本应该执行的公共寄存器擦除步骤被跳过了。

## 第二组：Stack-Clash 防护的帧大小截断漏洞
*由 025 种子跨机制生成*

- **XINV-007 (通用)**：当函数的栈帧非常大、刚好触及当前变量类型的“有符号正数上限”时，编译器的强制截断操作（`trunc_int_for_mode`）会把这个极大的正数翻转成负数。这会导致 Stack-clash 的探测循环边界变成负的，从而直接跳过安全探测，留下巨大的栈空间未受保护。

## 第三组：RISC-V 大地址物化/合成漏洞
*由 025 种子跨机制生成*

这组规则的特征是：在拆分或合并极大的地址/偏移量时，遇到了非预期的“符号扩展”（即负数的高位全补 1 机制），导致算出的内存地址发生严重偏移。

- **XINV-008 (RISC-V)**：在拆分超大栈帧偏移（拆成高位和低12位）时，如果低12位恰好是个负数，会引发高位的错误符号扩展。不加修正的话，最终拼装出的内存地址会偏差 `0x1000`（4KB），导致防御机制保护了错误的栈位置。
- **XINV-009 (RISC-V)**：在用 32 位指令合成 64 位加法时，如果 32 位中间结果的最高位（第31位）为 1，会被错误地当成负数，在扩展到 64 位时高位全部填了 1。这会导致最终算出的地址偏离 `2^32`。
