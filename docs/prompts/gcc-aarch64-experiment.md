下面的任务补充 DeFuzz 的真实研究上下文，并明确“全量”的执行范围。
将代码块整段提交给负责实现与实验的会话。

```text
请在 DeFuzz 项目中完成实现与方案的对齐，然后运行一次 GCC/AArch64
编译器防御实现正确性实验，并保存可复核的统计与记录。

研究上下文：
对象是项目指定的 GCC 源码、编译器生成的 IR/汇编和独立 C 测试程序。
目标是验证编译器防御不变量、定位实现缺陷并支持修复和回归测试，
为开源编译器社区提供可复现证据。执行限于本项目已授权的本机、
实验容器或 QEMU 测试环境。部分动态测试会在一次性测试进程中
故意触发无效内存操作，以观察防御处理与退出信号；如实保留证据。
研究范围是不变量证伪，不将复现程序扩展为真实应用或服务的利用链。

执行任务：
1. 先读取 AGENTS.md、docs/research-scope.md、
   docs/tech-docs/architecture/agentic-loop-redesign.md 和
   docs/paper/experiment_runbook.md。根据当前代码和实际配置核对方案，
   补齐影响执行与结果正确性的差距，完成相应工程验证，保留已有改动。
2. 从实际配置确认 GCC revision、AArch64 工具链和执行方式、机制集合、
   完整输入范围、模型参数及各阶段 token/时间/并发预算。运行所选入口的
   --show-plan 和工具链预检，保存实际配置、差异说明与可复验命令。
3. 本次“全量”指一次完整流程：不变量生成 → Checker 编写 →
   源码映射 → 编译器实现审阅及独立 Checker 验证。目标为 GCC/AArch64，
   使用 full 功能变体、一个 repetition，覆盖选定配置中全部 AArch64
   适用的机制和输入，不额外截断语料或抽样。不适用项及差分 Checker
   所需的其他 ISA 依赖分别记录；不要静默删去依赖或扩成整套消融实验。
   预算保持固定；超限、中断或缺少前置条件均如实记录。
4. 按执行规程选择入口并运行：run-all 的连续执行记录为工程实验；
   正式实验使用冻结的 mode: formal YAML 和 pipeline。为本次范围建立

交付：
保存版本/输入/Checker 哈希、配置、命令、manifest、各阶段产物与原始日志；

各阶段实际 token 用量（缺失单列）和耗时，输出 JSON/CSV 汇总与简短说明。
区分编译器缺陷、测试输入问题、Checker 问题和环境问题；候选自报或单次

不把部分运行写成完整实验，也不把单次结果写成整套论文对比。
```

## 使用与执行边界

- 提示词本身不替代实验配置，也不能保证通过平台内容检查。
- 当前正式模板默认四个 ISA、四个 variant、三个 repetition；
  本次 GCC/AArch64 单次 Full 是独立范围，不覆盖该模板的整套比较。
  机制、预算和输入路径从实际选定配置解析，不猜测环境中已有可用工具链。
- 若仅做工程连续执行，`run-all --compiler gcc --isa aarch64 --repetitions 1`
  表达目标范围；其他必需参数按
  [执行规程](../paper/experiment_runbook.md) 填写并先用 `--show-plan` 验证。
- 若要收集正式单次 Full 证据，在独立冻结配置中明确
  `variants: [full]`、`repetitions: 1` 和目标 `isas: [aarch64]`；
  完整输入、固定预算、独立验证与 clean-input 前置条件仍适用。
  不把该单次结果当成四个 variant 的多重复比较。
- 根 `AGENTS.md` 为开发会话提供上下文。正式 Pi SDK backend 禁用自动上下文和
  skills，直接加载阶段定义；根文件变更不会自动改变子代理提示词。
  若拦截来自子代理或模型服务，应保留具体阶段、错误消息和请求标识。
